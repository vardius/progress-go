## What Advance costs

`Advance` is one atomic add on the bar's counter. On one goroutine it takes about 2 ns and never allocates.
When many goroutines advance the same bar at once, they take turns on that one counter, and each call costs
more: see [Benchmarks](../benchmarks/). That is still far below the cost of any real piece of work, but if each
of your units is tiny, count them locally and advance once per batch:

```go
for i, row := range rows {
	insert(row)
	if (i+1)%1000 == 0 {
		bar.Advance(1000)
	}
}
bar.Advance(int64(len(rows) % 1000))
```

## The redraw timer

On a terminal, `Start` draws the bar and sets a timer. Each time it fires, the bar reads the count, draws a frame,
and sets the timer again, 100 ms on. `Advance` takes no part, so however many goroutines call it, and however
fast, the terminal gets ten frames a second.

`Start`, the redraws and `Stop` share one lock, which also orders the writes. `Stop` stops the timer and draws the
last frame under that lock, so once `Stop` returns, the bar never writes again, even if a redraw was due.

<Aside>
A bar that isn't stopped keeps its timer running. Call `Stop` when the work ends, on every path: a `defer` works
if you don't need its error.
</Aside>
